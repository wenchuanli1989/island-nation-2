# Engine 校验责任与精简记录

本记录中的验证对应简化校验重构时的源码。此次重构采用当前格式的可信完整存档契约：文件由正确业务状态生成、完整持久化并正确读取；所有模块 meta 与实体来自同一提交。当时存档版本为 15；后续移除任务 `result` 字段后升至 16；新增人物异常状态、移除任务层级及任务暂停／恢复相关字段后升至 17；移除未使用的日程版本后升至 23；删除未使用的人物秒时间字段后升至 24；当前任务与行为全局列表直接持久化后为 25，保留版本拒绝及现有 CRC 配置和摘要策略，不提供历史格式迁移。

## 校验责任

- 公共入口负责访问资格、新输入和当前业务状态；shared queue/logger 保持独立公共契约。
- 加载按可信字段类型解码，构建数组、ID map、进程内引用和运行字段；不逐层复核相同持久事实。
- 实际分配失败、容器容量、分配字节数溢出、格式化及 IO 结果仍在实际操作处检查。
- 同一独占操作复用已取得的查询结果和仍有效的条件；跨异步消息继续检查请求身份和当前资格。
- 当前业务时间及新时长运算保持 32 位毫秒限制；0 与 UINT32_MAX 都合法。

## 不变量与边界

1. 人物与 data 同序配对，运行期数组稳定；任务池增删或扩容之后重新按 ID 定位任务。
2. 加载只接收当前格式正确完整快照，包含正确 ID 游标；手工导入、损坏或不完整世界不属于此契约。
3. 睡眠不再维护建筑许可，固定使用主通道；任务请求、规划与草案提交仅在引擎内部产生，客户端不得直接提交，也不为测试提供对外任务提交方法或消息类型。任务 ID 由执行器分配，规划请求和计时登记不持久化，合法活动存档加载后直接续跑，旧异步消息仍须按当前身份过滤。
4. 低精力自主规划请求由唯一执行线程生成；结果消费时重验请求身份和当前资格。自然需求结算只衰减，不会使原低精力条件失效。
5. Nav 已登记实体 ID 不得改写，map 由加载、道路新增及排序刷新维护；邻接和状态的公开可写性不被误当作不可变保证。
6. Nav 实体上限为 2^30，与 storage 的 khashl 容量不同；每路网 3000 路口和邻接写入容量保护继续保留。
7. 人物 NORMAL／EXCEPTION 状态随存档保存。执行器发现 FAILED／CANCELLED 任务结果即置人物异常；执行入口及 Stop 结算跳过异常人物，迟到草案只清理所有权。当前不提供任务停止、取消、暂停或恢复接口。
8. 准确保留实际资源失败与新运算边界；删除不再需要的临时资源时，其分配及失败分支一起删除。
