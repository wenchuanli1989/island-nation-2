# 动机与任务规划需求说明

适用范围：human 模块的动机规划与任务规划链路（触发 → 规划器 → 执行器提交）、动机与任务规划的下次规划时刻及规划重试、三类规划请求的期限、执行器对行为规划结果的复核，以及推进层只读预测中与动机复评有关的部分。行为规划的触发方式、规划重试和规划策略不在本次范围（第 11 节）。

依据：[项目宪法第六章“简化校验”](项目宪法.md#六简化校验)中的“规划判断默认允许信息差”“执行器保留的复核”“规划请求不设期限”三条。

## 1. 目标

1. **动机只指方向。** 动机说明人物长期要满足的需求（例如恢复精力），不再表达“当前是否需要行动”。
2. **规划器自主决定。** 是否为动机生成任务、一次规划满足哪些动机，由任务规划器根据已有动机和读锁快照判断。什么时候需要再看一次，由动机和任务规划器各自判断；需要以后再看时，在结果中给出下次规划时刻，由执行器并入人物唤醒。
3. **执行器减负。**
   - 不复评动机，也不判断动机是否需要新工作；
   - 只看廉价信号（标志、请求槽、下次规划时刻；行为另看重试时刻）决定何时请求规划；
   - 收到三类规划结果后只做第 2 节规定的复核，然后提交；动机和任务不再按结果分类设重试（第 5.3 节）；
   - 规划请求不设期限，投递请求不再改变人物唤醒。
4. **推进层减负。** 只读预测不再计算动机复评时刻，只为行为、任务决策和任务截止点等执行事实提供唤醒时刻。
5. **规划线程不登记计时。** 三类规划器都不调用 GameTimer，人物仍只保留一个唤醒计时。

## 2. 原则

- **允许信息差的判断：** 本需求涉及以下规划判断，均按宪法第六章默认允许信息差，不要求更严格的复核：
  - 动机的建立与终结；
  - 任务的建立、撤销与取消，为哪些动机安排工作；
  - 下次何时规划；
  - 行为计划的步骤内容与参数（例如睡眠时长）；
  - 运行任务是否接受插入。
- **执行器只拒绝复核不通过的条目。** 从规划器作出判断到执行器提交之间，人物或世界的信息可能已经变化，例如精力变化、新的外部信息到达、动机被新建或终结、动机下又接受了新任务、运行任务的应激选择改变。执行器不检测、不拒绝、也不回滚这类变化；只有第 3.4.1、4.3.1、6.2 节的复核不通过的条目才被拒绝。这些复核对应宪法第六章的请求身份、结构性条件和身份锚点三类。
- **执行判定使用实时事实。** 行为能否启动（执行条件、行为类型互斥、行为依赖）、行为终态和任务决策，仍在每个边界按实时事实判定；过时的判断由它们在后续边界纠正，例如精力被外部补到目标值后，任务决策取消睡眠任务。
- **结算不属于时效性检查。** 执行器提交前仍把人物结算到本次时刻，这是写入的前提。
- **信息差不是玩法上的反应时间。** 信息差的大小取决于队列积压和规划负载，不可控，也不便复现。需要反应时间时，在规则中显式设计。
- 动机终结后如果又出现同类需求，由动机规划器建立新动机（使用新 ID），不恢复旧动机。
- 下次规划时刻只是一次规划机会，不是业务事实。早到或晚到，都由到点后的那次规划按当时的事实重新判断。

## 3. 动机

### 3.1 动机只保存方向与历史

- 动机保存以下内容：
  - 类型、归属人物；
  - 状态：有效、达成、失败或撤销；
  - 实施次数、最近 10 条明细、最近失败原因；
  - 睡眠工作身份所需的需求轮次（`need_round`、`round_task_id`）。
- 删除“行动需要”标志 `DOMINO_MOTIVATION_FLAG_ACTION_NEEDED` 和动机候选操作 `DOMINO_MOTIVATION_CANDIDATE_ADJUST`。
- 删除执行器使用的三个动机判断函数：`dominoHumanMotivationDesiredAction`、`dominoHumanMotivationNeedsReview`、`dominoHumanMotivationNeedsNewWork`。“现在要不要为恢复精力去睡觉”这类判断移入任务规划策略（第 4.1 节）。

### 3.2 何时发起动机规划

人物的动机请求槽空闲、并且动机待评估标志已置位时，发起请求。

动机待评估标志属于本会话运行态，以下事件置位：

| 事件 | 置位时机 |
| --- | --- |
| 加载 | `InitAfter` 为每个人物置位 |
| 外部信息 | 登记外部信息（当前只有测试验收专用入口） |
| 任务结束 | 人物的任务进入执行终态或被撤销 |
| 下次规划时刻到达 | 执行器结算后调度时，人物的动机下次规划时刻已到（第 5.2 节） |

- **清除规则：** 投递请求时清除，结果不改变标志（第 5.3 节）。
- **删除“无有效动机”信号：** 人物没有有效动机本身不再发起请求。是否新建动机、什么时候再看，由动机规划器决定，并随结果给出下次规划时刻（第 5 节）。
- 原设计中与行动需要配套的“复评时刻”已删除：执行器不复评动机，推进层也不预测复评时刻（第 8 节）。动机的下次规划时刻只是一次规划机会，与任务规划使用同一机制。
- 执行器不再检查外部信息是否需要回应动机。
- 请求优先级规则保持不变。

### 3.3 动机规划器职责

- 依据读锁快照（必要时做只读预测），对人物的动机给出建议：新建（`CREATE`）、终结（`TERMINATE`）或无需调整（`NO_CHANGE`）。一份提案可以包含多条建议。
- 决定下次规划时刻，随结果返回（第 5 节）。
- 新增终结操作 `DOMINO_MOTIVATION_CANDIDATE_TERMINATE`，条目携带两项：
  - `motivation_id`：要终结的动机；
  - 终态：达成、失败、撤销三者之一。
- 条目都不带 `expected_*` 依赖字段。随 `ADJUST` 一起删除 `action_needed_flag`、`expected_action_needed_flag`，`CREATE` 也不再携带行动需要。
- 第一阶段生产策略：人物没有有效的恢复精力动机时新建一项，否则返回 `NO_CHANGE`；两种情况的下次规划时刻都为“无”。计算预算耗尽返回 `NO_PLAN` 时，按第 5.1 节给出时刻。恢复精力是维持型动机，不终结。

### 3.4 执行器处理动机规划结果

#### 3.4.1 保留的复核

| 复核项 | 不满足时 |
| --- | --- |
| 请求身份（第 7 节） | 旧结果或重复结果只释放载荷 |
| `TERMINATE`：动机存在、属于该人物、状态为 `ACTIVE` | 忽略该条目，因此重复终结不会产生副作用 |
| `CREATE`：每人 8 个、全局 80000 个的容量上限；同类型已有有效动机时复用原动机（现有规则） | 超出容量时，按现有必要／可选规则拒绝 |

#### 3.4.2 结果处理

结果分类不再决定重试和标志：待评估标志已在投递请求时清除，结果只决定动机的下次规划时刻（第 5.2、5.3 节）。

| 结果 | 下次规划时刻 |
| --- | --- |
| 提案被接受（包括可选建议被省略）、`NO_CHANGE`、`NO_PLAN` | 取结果给出的值；“无”时清除 |
| 整份候选被复核拒绝 | 处理时刻 + `retry_delay_ms` |

处理后人物仍没有有效动机时，执行器不另设重试：删除“无有效动机”信号后，空结果不会立即引发新请求。

提案实际新建或终结了动机时，在同一次写锁内置人物的任务待规划标志（第 4.2 节）。

### 3.5 终结后的后续事项

以下各项在提交终结的同一次写锁内完成：

1. **写入终态。**
2. **不再承接新工作。** 任务规划器不应再为该动机安排工作；挂在该动机下的新任务，执行器按“所属动机须为 `ACTIVE`”的复核拒绝（第 4.3.1 节）。
3. **处理关联任务。**
   - 尚未启动的任务（没有执行部分）撤销并回收，不制造执行记录。带义务的任务类型可以在自己的规则里改为继续保留、等待执行。
   - 已经启动的任务继续执行，直到自身结束。
   - 这些任务以后成功，仍给原动机计次并追加明细，但不恢复动机的有效状态。
4. **回收动机。** 动机已终结、并且没有任何关联任务时就回收。需要在两个时机检查：
   - 提交终结时，在第 3 项撤销之后，如果动机没有关联任务，立即回收；
   - 回收某个任务时，如果所属动机已终结，而这是它的最后一个任务，一并回收动机。

   回收后，动机从人物的动机列表中移除，ID 不复用。在途的请求或提案如果引用了已回收的动机，按“动机不存在”处理。
5. **去重依据的归属。**
   - 以动机自身为来源的工作（例如睡眠的“动机 + 需求轮次”），去重依据随动机回收一起丢弃，因为动机终结后不会再有新工作。
   - 有外部业务来源的工作，去重依据放在业务来源上，不依赖动机是否还存在。
6. **置任务待规划标志。** 让任务规划器看到新的动机集合。

终结只来自动机规划器自己的提案，规划器在提交前就知道终结后剩下的动机集合。终结后是否需要、什么时候需要再规划动机，由它随结果给出下次规划时刻；执行器不因人物没有有效动机而发起动机规划（第 3.2 节）。

## 4. 任务规划

### 4.1 任务规划器职责

- **请求范围：** 任务规划请求以人物为范围（触发范围 `DOMINO_HUMAN_PLAN_SCOPE_HUMAN`），不再绑定单个动机。规划器在同一次读锁内读取以下事实：
  - 人物的全部有效动机；
  - 已接受任务及待执行队列；
  - 外部信息；
  - 规划时刻的需求值（用只读预测）。
- **规划器自行决定：**
  - 是否生成任务、为哪些动机生成、生成几个。一份候选可以同时包含为不同动机建立的任务，也可以一个都不建。
  - 是否撤销或取消已有任务（`CANCEL`）。
  - 下次规划时刻，随结果返回（第 5 节）。
- **动机归属：** 每个任务仍只归属一个动机。所属动机须为该人物的有效动机；任务成功时，只给所属动机计次并追加明细。数据结构不变。回应外部信息的任务挂在哪个有效动机下，也由规划器决定。
- **第一阶段生产策略（恢复精力 → 睡眠）：**

  | 情况 | 规划结果 | 下次规划时刻 |
  | --- | --- | --- |
  | 预测规划时刻的精力不高于睡眠触发值（默认 30），且上一轮睡眠工作已结束（`round_task_id` 为 0） | 提出下一轮睡眠任务，工作身份为动机 + `need_round + 1` | 无 |
  | 上一轮已结束，但精力高于触发值 | `NO_CHANGE` | 预测精力首次降到触发值的时刻 |
  | 本轮睡眠工作尚未结束 | `NO_CHANGE` | 无；任务结束时会置任务待规划标志 |
  | 计算预算耗尽 | `NO_PLAN` | 规划时刻 + `retry_delay_ms`（第 5.1 节） |

  预测精力首次降到触发值的时刻：
  - 没有推进中的行为时，直接按自然衰减计算；
  - 有推进中的行为时，在计算预算内按共用的只读预测逐个边界推进；预算内无法确定的，给出已推进到的边界，作为保守时刻。
- **回应外部信息的任务：** 仍只在受控规划场景中产生。

### 4.2 何时发起任务规划

人物的任务请求槽空闲、并且任务待规划标志已置位时，发起请求。执行器不再做以下事情：
- 逐个动机调用 `dominoHumanMotivationNeedsNewWork`；
- 按动机等待次序选择触发范围；
- 把人物任务数量作为发起条件（容量在提交时复核）。

任务待规划标志属于本会话运行态，以下事件置位：

| 事件 | 置位时机 |
| --- | --- |
| 加载 | `InitAfter` 为每个有有效动机的人物置位 |
| 动机集合变化 | 动机规划结果提交后，实际新建或终结了动机 |
| 任务结束 | 人物的任务进入执行终态或被撤销 |
| 外部信息 | 登记外部信息（当前只有测试验收专用入口） |
| 人物输入变化 | 测试验收专用的精力、睡眠条件输入实际改变了值 |
| 下次规划时刻到达 | 执行器结算后调度时，人物的任务下次规划时刻已到（第 5.2 节） |

- **清除规则：** 与动机待评估标志相同，投递请求时清除，结果不改变标志（第 5.3 节）。
- **不触发的情况：** 运行任务启动、让位不置位。两者会改变待执行队列版本；指定插入位置的候选因此被整份拒绝时，由第 5.3 节的兜底时刻再规划。
- **优先级：** 规则保持不变。精力不高于 10 时使用高优先级，否则使用普通优先级。
- **删除任务规划重试：** 删除动机上的 `task_retry_at_ms`、`DOMINO_MOTIVATION_FLAG_TASK_RETRY_VALID` 和运行态 `task_wait_seq`；人物不新增任务规划重试字段（第 5.3 节）。

### 4.3 执行器处理任务规划结果

#### 4.3.1 保留的复核

保留的复核只涉及身份、去重、归属、状态和容量：

| 复核项 | 不满足时 |
| --- | --- |
| 请求身份（第 7 节） | 旧结果或重复结果只释放载荷 |
| `CREATE`：任务类型有对应规则，目标值不超过需求上限 | 拒绝该条目 |
| `CREATE`：所属动机存在、属于该人物、状态为 `ACTIVE` | 拒绝该条目 |
| `CREATE`：已有未终结任务的工作身份与建议相同 | 复用原 `task_id`，不新建 |
| `CREATE`：同份候选内有更早的相同建议 | 复用更早条目，不新建 |
| `CREATE`：来源为动机时，`work_source_id` 等于所属动机 ID | 拒绝该条目 |
| `CREATE`：来源为外部信息时，对应人物当前尚未承接的外部信息（来源和轮次一致），且同份候选只承接一次 | 拒绝该条目 |
| `CREATE` 睡眠：来源为所属动机，所属动机为恢复精力 | 拒绝该条目 |
| `CREATE` 睡眠：读取时轮次 `expected_motivation_round` 等于当前 `need_round`，`work_round` 为其下一轮 | 拒绝该条目 |
| `CREATE` 睡眠：上一轮已结束（`round_task_id` 为 0），轮次未耗尽 | 拒绝该条目 |
| `CREATE`：每人 32 个、全局 320000 个任务，以及待执行队列容量 | 按必要／可选规则拒绝 |
| `CREATE`：指定插入位置时，位置有效，且待执行队列版本与读取时一致 | 拒绝该条目 |
| `CANCEL`：任务存在、属于该人物、未终结；同份候选不重复取消 | 拒绝该条目 |

#### 4.3.2 结果处理

与动机相同（第 3.4.2 节）：任务待规划标志已在投递请求时清除，结果只决定任务的下次规划时刻（第 5.2、5.3 节）。

| 结果 | 下次规划时刻 |
| --- | --- |
| 提案被接受（包括可选建议被省略）、`NO_CHANGE`、`NO_PLAN` | 取结果给出的值；“无”时清除 |
| 整份候选被复核拒绝 | 处理时刻 + `retry_delay_ms` |

## 5. 下次规划时刻与规划重试

### 5.1 规划器随结果给出

- 动机和任务规划线程处理有效请求后，各自决定该人物这一类下一次需要重新规划的时刻，或者决定“无”，随结果一起返回。每种结果分类都给出，包括 `NO_PLAN`。
- 结果消息 `DominoHumanPlanResultMessage` 新增下次规划时刻及其有效标志。动机和任务规划使用，行为规划恒为无效（第 11 节）。
- 时刻须晚于规划时刻，计算遵循宪法第七章的范围检查；超出 32 位业务毫秒时视为“无”。
- 第一阶段生产策略：
  - 动机：按第 3.3 节，新建或 `NO_CHANGE` 都给“无”；
  - 任务：按第 4.1 节的表格；
  - 两类在计算预算耗尽返回 `NO_PLAN` 时，都给出规划时刻 + 重试延迟 `retry_delay_ms`（默认 3000ms）。
- 三类规划器都不登记 GameTimer 计时，也不保存每人物的计时状态。

### 5.2 执行器保存与唤醒

- 人物运行态新增动机、任务两类各自的下次规划时刻及其有效标志，只在本会话有效，不持久化。
- 处理身份匹配的动机或任务规划结果时，无论结果分类，都用结果中的时刻覆盖该类的当前值；结果为“无”时清除。整份候选被复核拒绝时例外，按第 5.3 节设兜底时刻。每个人物同一时间每类只有一个请求，覆盖不会让旧判断盖过新判断。身份不匹配的旧结果或重复结果只释放载荷，不改变时刻。
- 结算后调度时，若某类的下次规划时刻已到：清除该时刻，置该类的标志（动机待评估标志或任务待规划标志），随后按第 3.2、4.2 节发起请求。
- 汇总人物唤醒时，有效的下次规划时刻参与（第 8 节）。人物仍只保留一个唤醒计时，不新增通知类型，也不需要核对计时器身份。

### 5.3 取消动机与任务的规划重试

现有实现在结果到来后，按结果分类决定是否设 3000ms 重试、是否保留标志。动机和任务改为：

- **标志在投递请求时清除，结果不改变标志。** 请求在途期间新置位的标志保留，结果处理后按第 3.2、4.2 节再发起一次请求。
- **再次规划的时机由规划器给出。** 包括 `NO_PLAN` 在内，执行器都使用结果中的下次规划时刻（第 5.1 节），不按结果分类设重试。
- **整份候选被复核拒绝时设兜底时刻。** 执行器把该类的下次规划时刻设为处理时刻 + `retry_delay_ms`，超出 32 位业务毫秒时视为“无”。只有可选条目被省略时不算整份拒绝，仍取结果给出的时刻。需要兜底的原因：
  - 规划器给出的时刻以候选会被接受为前提，例如提出睡眠任务后给“无”；
  - 导致拒绝的变化不一定置标志，例如待执行队列版本在运行任务启动、让位时变化，两者按第 4.2 节不置标志；规划器缺陷导致的类型或参数非法也没有事件。没有兜底时，人物可能不再规划。
- **删除重试字段与发起闸门。**
  - 删除人物上的动机规划重试时刻 `motivation_retry_at_ms` 及其有效标志；
  - 任务规划不新增重试字段，动机上的任务重试字段按第 4.2 节删除；
  - 发起条件不再包含“没有未到期的重试”。
- **影响：**
  - 规划失败或被拒之后的等待期内，新的置位事件立即发起请求，不再被重试拦住。每个事件至多引起一次请求，“每人物每批每类至多新投递一次”仍然限制投递频率。
  - 读档后不沿用会话前的重试等待，`InitAfter` 置标志后每人立即规划一次。重试只是节流，不是业务事实，按宪法第 3.7 节可以不保存。
- **行为不变。** 行为规划仍按 `dominoHumanTaskNeedsBehaviorPlan` 扫描触发；`NO_PLAN` 之后计划缺口通常仍在，删除重试会在空结果与新请求之间忙循环。行为保留第 6.4 节的重试，与标志触发一起调整（第 11 节）。

### 5.4 跨会话与生命周期

- 下次规划时刻不跨会话保存。加载后，`InitAfter` 为每个人物置动机待评估标志，为每个有有效动机的人物置任务待规划标志，规划器重新规划，并重新给出时刻。恢复依据是已保存的动机、任务、需求值和结算游标，满足宪法第 3.7 节“跨会话工作必须有恢复依据”的要求。
- 不新增资源或线程；停止顺序、冻结末批、销毁和重建都不需要额外处理。

## 6. 执行器处理行为规划结果

### 6.1 范围

- 只改变执行器复核行为规划结果的方式。以下内容保持不变：
  - 触发条件（`dominoHumanTaskNeedsBehaviorPlan`）；
  - 规划重试（第 6.4 节），结果中的下次规划时刻恒为无效；
  - 请求优先级；
  - 行为规划器的生产策略；
  - 运行任务的应激规则。
- 允许信息差的判断：
  - 替换（`REPLACE`）给出的步骤内容与参数，例如按规划时刻预测的精力算出的睡眠时长；
  - 运行任务是否接受插入（`INSERT`）。

### 6.2 保留的复核

条目被拒绝时，按现有必要／可选规则决定整份候选是否被拒绝。

| 复核项 | 不满足时 |
| --- | --- |
| 请求身份（第 7 节） | 旧结果或重复结果只释放载荷 |
| 公共：任务存在、属于该人物、未终结；步骤区范围有效；同份候选内同一任务至多一个条目 | 拒绝该条目 |
| `REPLACE`：任务当前计划版本等于读取时的 `expected_plan_version` | 拒绝该条目 |
| `REPLACE`：任务尚未处于“完成条件已成立”状态 | 拒绝该条目 |
| `REPLACE` 声明依赖当前行为时：各通道当前行为与读取时一致（0 表示要求该通道没有当前行为） | 拒绝该条目 |
| `REPLACE` 步骤：类型有对应规则且参数合法，通道有效，不带标志；依赖种类合法、状态为待定，只指向本条目更早的步骤或本任务当前的非插入行为；伴随依赖的来源在另一通道 | 拒绝该条目 |
| `INSERT`：任务为人物的运行任务；步骤数非零；同份候选只有一个插入条目 | 拒绝该条目 |
| `INSERT`：人物有尚未承接的外部信息，且外部信息轮次等于读取时的 `expected_stimulus_round` | 拒绝该条目 |
| `INSERT` 步骤：只用辅助通道，没有依赖，类型有对应规则且参数合法 | 拒绝该条目 |
| 容量：任务未来步骤与未回收行为记录合计不超过 255；全局计划项不超过 1000000 | 按必要／可选规则拒绝 |

### 6.3 保留锚点的原因

- **计划版本：** 规划器读取之后，执行器可能已经启动并消费了步骤，或因让位清空了计划，这些都会更新版本。不核对版本时，旧的替换方案会把已经开始的步骤再安排一次，有效果的行为（例如交易、拾取）就会重复结算。
- **当前行为：** 依赖来源和替换的衔接点都以读取时的当前行为为准；当前行为变化后，依赖可能指向错误的行为。
- **外部信息尚未承接且轮次一致：** 外部信息轮次是插入步骤回应哪一条外部信息的唯一身份。轮次变化说明来了新的外部信息，不核对时新信息会被旧方案标记为已承接，却没有得到回应。尚未承接这一条件也让回应任务与插入步骤互斥：两者同时在途时，只有先提交的一方承接外部信息，另一方被拒绝。

### 6.4 结果分类

| 结果 | 处理 |
| --- | --- |
| 提案被接受，或 `NO_CHANGE` | 处理后该任务仍满足行为规划触发条件时，设 3000ms 重试；否则不设 |
| `NO_PLAN`、复核拒绝 | 沿用现有 3000ms 重试 |

行为规划仍按 `dominoHumanTaskNeedsBehaviorPlan` 扫描触发。提交后的这次判定只决定是否设重试，不影响结果是否被接受，用来避免在空结果与新请求之间忙循环。动机和任务已取消规划重试（第 5.3 节）；行为在扫描触发下仍需要这条重试，与标志触发一起调整（第 11 节）。

## 7. 规划请求不设期限

### 7.1 前提

宪法第六章要求的前提如下，前两项现有实现已经满足，第三项在删除期限判断（第 7.2 节）后满足：
- 每次规划计算有预算上限（默认 512），预算耗尽时返回 `NO_PLAN`；
- 请求和结果投递失败直接致命退出；
- 规划线程只跳过身份不匹配的请求，即已经失效的请求。

因此每个有效请求在本次会话内恰好得到一个结果，请求槽不会因为结果丢失而一直被占用。

### 7.2 改动

- 请求槽只保存请求 ID、优先级和触发范围，删除截止点 `deadline_ms`。
- 删除三类规划器的请求期限配置 `request_timeout_ms`（默认 3000ms）。
- 执行器：
  - 删除 `expireSlots`、投递时的截止点计算及溢出检查；
  - 删除结果的过期分支，结果只核对请求身份；
  - 汇总人物唤醒时不再包含请求截止点。
- 规划线程出队后只核对请求身份，不再按期限跳过请求。
- 删除过期结果的统计计数。
- 重试延迟 `retry_delay_ms`（默认 3000ms）保留，用于：
  - 行为规划的重试（第 6.4 节）；
  - 动机和任务整份候选被拒时的兜底时刻，以及第一阶段策略 `NO_PLAN` 给出的时刻（第 5 节）。

### 7.3 影响

- 投递请求不再改变人物唤醒：不再有每次规划一次的计时取消、登记和空唤醒。
- 排队较久的请求照常计算，结果照常处理；不再出现“过期 → 重试 → 重新投递”的循环，队列中也不再积压作废请求。
- 请求等待期间紧迫性升高（例如精力降到 10 以下）时，不再借超时重投提升优先级。普通请求仍由每批固定配额保证处理机会；按新紧迫性重投不在本次范围（第 11 节）。

## 8. 推进层与执行器唤醒

- 只读预测 `dominoHumanPredictNextCheck` 删除动机复评部分：
  - 边界事件判断中的动机重评检查；
  - 没有推进中的行为时，“精力降到触发值”的复评时刻。
- 保留行为结束、任务决策变化、任务截止点等执行事实的预测。
- 执行器唤醒汇总以下时刻，人物只保留最早的一个登记：
  - 行为规划的重试时刻（保存在任务上，第 6.4 节）；
  - 动机和任务规划的下次规划时刻；
  - 只读预测给出的检查时刻。

  不再汇总请求截止点，也不再汇总动机和任务的重试时刻（第 5.3 节）。
- 需求达到阈值时的检查时机，只由任务规划给出的下次规划时刻提供。

## 9. 持久化

- 动机终态保存在存档的 `status` 字段中；回收后的动机不再保存。
- 以下内容属于本会话运行态，不保存：动机待评估标志、任务待规划标志、动机和任务的下次规划时刻。加载后由 `InitAfter` 统一置标志（第 3.2、4.2、5.4 节）。
- 存档格式变化：
  - 动机删除 `flags` 和 `task_retry_at_ms` 字段：删除行动需要和任务重试之后，`flags` 已经没有有效位；
  - 人物删除动机规划重试字段 `motivation_retry_valid`、`motivation_retry_at_ms`，不新增任务规划重试字段（第 5.3 节）；
  - 任务上的行为规划重试字段 `behavior_retry_at_ms` 保持不变；
  - 存档版本由 30 升为 31，拒绝旧格式。
- 行为规划结果复核的调整（第 6 节）和请求期限的删除（第 7 节）不改变存档格式。

## 10. 删除的检查（迁移说明）

相对现有实现，执行器复核规划结果时删除以下检查。它们都在复核判断依据，按宪法第六章不再进行。请求期限的删除见第 7.2 节。

**动机**

- 结算后“是否仍需本次动机规划”的检查（`scopeStillNeeded` 的动机分支）。
- 提交后“问题是否已解决”的业务复查。
- `ADJUST` 对 `expected_action_needed_flag` 的核对。

**任务**

- 结算后“是否仍需本次任务规划”的检查（`scopeStillNeeded` 的任务分支）。
- 提交后“问题是否已解决”的复查，原来用于决定是否设重试。
- 睡眠新工作对行动需要和精力的业务复核（`dominoHumanMotivationNeedsNewWork`）。
- 回应任务的两项复核：
  - 运行任务的应激选择是否为“需要回应任务”（`dominoHumanStimulusNeed`）；
  - 所属动机须为回应联系类型。

  运行任务此时如果选择接受插入，回应任务照常入队；是否让位，仍由启动时的应激规则决定。

**行为**

- 结算后“是否仍需本次行为规划”的检查（`scopeStillNeeded` 的行为分支）：
  - 任务存在、归属、未终结，由第 6.2 节的公共复核覆盖；
  - 计划缺口、能否安排行为（任务规则的 `has_plan_gap`、`can_plan_behavior`），不再复核。
- `INSERT` 对“运行任务的应激选择仍为接受插入”的复核（`dominoHumanStimulusNeed`）：运行任务此时即使已改为完全让位，插入步骤仍照常提交并承接外部信息。

**规划重试**

以下逻辑随第 5.3 节删除，行为规划的重试不在其中：

- 动机和任务结果按分类设 3000ms 重试，并按分类保留或清除标志；
- 动机“处理后仍没有有效动机时设重试”的防忙循环；
- “无有效动机”发起信号；
- 发起条件中的“没有未到期的重试”，以及动机、任务重试时刻参与唤醒汇总；
- 人物上的动机规划重试字段及其存档。

## 11. 不在本次范围

- 行为规划的触发方式：仍按 `dominoHumanTaskNeedsBehaviorPlan` 扫描触发；扫描范围已于 2026-11-20 缩小为运行任务和待执行队首（见第 14 节决策记录）。执行器的主要开销在这类逐任务业务判断和唤醒预测上，改为第 4.2 节那样的标志触发，是后续进一步减负的方向；是否采纳，按代表性负载测量决定。采纳时一并处理：
  - 行为结果携带下次规划时刻；
  - 按第 5.3 节取消行为规划重试，删除任务上的 `behavior_retry_at_ms` 和 `DOMINO_TASK_FLAG_BEHAVIOR_RETRY_VALID`，唤醒汇总不再遍历任务；
  - 列全置位事件，例如任务首次启动、行为进入终态、让位后恢复、登记外部信息、加载。漏掉事件会让任务停在没有计划的状态，扫描触发没有这个风险。
- 行为规划器的生产策略。
- 请求优先级规则，以及请求等待期间按新紧迫性撤销并重投（第 7.3 节）。
- 运行任务的应激规则本身，即接受插入或完全让位的选择及让位时机。
- 回应联系动机及回应任务的生产策略：仍只在受控规划场景中产生。
- 动机终结：生产策略不启用，恢复精力动机不终结；终结流程只在受控规划场景中验证。

## 12. 验证

通过受控规划场景（playground 夹具）验证，不增加客户端接口。需要覆盖以下情况：

**动机**

- 第 3.2 节的各个置位事件分别发起动机规划；人物没有有效动机本身不发起；执行器不调用业务判断函数（相关函数已删除）。
- 请求在途期间新置位的待评估标志保留，结果处理后再发起一次请求。
- 规划器选择不建动机并返回 `NO_CHANGE` 时，执行器不再发起请求，直到下一个置位事件或下次规划时刻，不出现忙循环。
- 正常终结、重复终结、目标动机已回收。
- 信息差：作出判断后条件已经变化，或动机下又接受了新任务，结果仍照常提交。
- 终结后：
  - 拒绝挂在该动机下的新任务；
  - 未启动的任务被撤销并回收；
  - 已启动的任务继续执行，成功后给原动机计次，但动机不恢复有效。
- 两个回收时机。

**任务**

- 请求以人物为范围；一份候选可以为多个动机建立任务；规划器选择不建任务时返回 `NO_CHANGE`，并清除标志。
- 第 4.2 节的各个置位事件分别发起任务规划；运行任务启动、让位不发起。
- 请求在途期间新置位的标志保留，结果处理后再发起一次请求。
- 信息差：
  - 判断之后精力变化、动机集合变化，结果仍照常提交；
  - 所属动机已终结或已回收时，拒绝该条目；
  - 回应任务不再复核运行任务的应激选择。
- 复核：同次工作复用；睡眠轮次不符、容量不足、队列版本不符时，按规则拒绝。

**下次规划时刻与规划重试**

- 精力高于触发值时，结果给出下次规划时刻；到点后执行器发起任务规划，并在精力达到触发值时建立睡眠任务。
- 动机规划器给出的下次规划时刻到点后，执行器发起动机规划。
- 每个身份匹配的动机或任务规划结果都覆盖该类的下次规划时刻：
  - 结果为“无”时清除；
  - `NO_PLAN` 取结果给出的时刻（第一阶段为规划时刻 + `retry_delay_ms`）；
  - 整份候选被拒时设为处理时刻 + `retry_delay_ms`；只有可选条目被省略时取结果给出的值。
- 指定插入位置的任务候选因运行任务启动或让位而被整份拒绝后，到兜底时刻再规划一次。
- 兜底等待期内登记外部信息等置位事件，立即发起请求。
- 本轮睡眠尚未结束时不给出时刻。
- 规划线程不调用 GameTimer；人物只保留一个唤醒计时；唤醒汇总不含动机和任务的重试时刻。
- 冻结末批、Stop、Destroy 后重建都正常；保存后读档，确认加载后每人动机、任务各规划一次（任务只针对有有效动机的人物），并重新给出时刻；存档中没有动机规划重试字段。

**请求期限**

- 投递请求不改变人物唤醒计时。
- 排队超过原期限（3000ms）的请求仍被计算，结果照常处理，不出现重试和重新投递。
- 每个有效请求恰好得到一个结果；旧结果或重复结果只释放载荷，不清除新请求。
- Stop 时留队的请求和结果被丢弃，读档后按标志重新规划。

**行为**

- 信息差：判断之后精力变化、运行任务的应激选择改为完全让位，结果仍照常提交；执行器不调用 `has_plan_gap`、`can_plan_behavior` 和 `dominoHumanStimulusNeed` 复核结果。
- 过时的步骤参数由执行判定纠正：替换提交后精力被外部补到目标值，任务决策照常取消睡眠任务。
- 计划版本不符时拒绝 `REPLACE`：规划之后执行器启动了步骤，或让位清空了计划，已经开始的步骤不会被再次安排。
- 声明依赖当前行为而当前行为已变化时，拒绝 `REPLACE`；任务完成条件已成立时，拒绝 `REPLACE`。
- `INSERT` 在以下情况被拒绝：外部信息轮次已变化（新的外部信息到达）；外部信息已被回应任务承接或已撤回；任务已不是运行任务。
- 回应任务与插入步骤同时在途时，只有先提交的一方承接外部信息。
- 接受或 `NO_CHANGE` 后任务仍需行为规划时设重试，不出现忙循环；`NO_PLAN`、拒绝设 3000ms 重试。

**推进层**
