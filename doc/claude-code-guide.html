入门 · A1

安装、登录与升级

claude installclaude authclaude updateclaude doctor

推荐用原生安装器，它会在后台自动更新。登录方式决定计费：订阅账号走套餐额度，API Key 按 token 计费。

系统要求

  • macOS 13+；Ubuntu 20.04+、Debian 10+、Alpine 3.19+；Windows 10 1809+（推荐装 Git for Windows，或直接在 WSL 里用）
  • 内存 4GB 以上（安装本身约需 512MB），x64 或 ARM64
  • Git 可选；claude plugin eval 和从本地仓库发起云端会话需要 Git 2.31+

curl -fsSL https://claude.ai/install.sh | bash -s 2.1.89    # 指定版本

claude --version     # 例如 2.1.329 (Claude Code)
claude doctor        # 只读体检：安装状态、设置文件校验、自动更新状态

教程：第一次登录

  1. 进入项目目录运行 claude。首次进入会先弹工作区信任对话框，确认后进入登录流程。
  2. 浏览器会自动打开。没打开就按 c 复制登录链接。在 SSH 远程机器上，把链接粘到本地浏览器登录，再把页面给出的 code 粘回终端的 Paste code here if prompted。
  3. 看到 Login successful 即完成。如果终端里粘贴不进去，退出后改用 claude auth login，它从标准输入读 code。
  4. 会话里运行 /status，确认登录方式是订阅账号还是 API Key。

登录方式与凭据优先级

同时存在多种凭据时，按下面的顺序取第一个：

顺序凭据典型用途
1CLAUDE_CODE_USE_BEDROCK / _VERTEX / _FOUNDRY走云厂商
2ANTHROPIC_AUTH_TOKEN网关的 Bearer token

claude auth login            # 在 shell 里登录
claude auth status --text    # 查看登录状态；2.1.318+ 会显示 Sign-in ends: 过期时间
claude auth logout

claude setup-token           # 无浏览器的服务器或 CI：生成长期 token（只打印、不保存）
export CLAUDE_CODE_OAUTH_TOKEN=你的token

# 两个账号互不干扰：各用一个配置目录
alias claude-work='CLAUDE_CONFIG_DIR=~/.claude-work claude'

会话内可用 /login 切换账号，/logout 退出并清除凭据。凭据位置：Linux 在 ~/.claude/.credentials.json（权限 0600），macOS 在钥匙串。

升级与卸载

  • 原生安装会在启动时和运行中检查更新，下次启动生效。手动升级用 claude update。
  • 已装好新版、想在当前会话立即生效：/restart（别名 /update），会重启并恢复会话。仅限订阅账号、原生 macOS/Linux。
  • 渠道设置 autoUpdatesChannel："latest"（默认）或 "stable"（约晚一周，跳过有严重回归的版本）。从 latest 切到 stable 可能降级，可同时设 minimumVersion。
~/.claude/settings.json
{
  "autoUpdatesChannel": "stable",
  "minimumVersion": "2.1.323",
  "env": {
    "DISABLE_AUTOUPDATER": "1"
  }
}

DISABLE_AUTOUPDATER 只停后台自动更新，claude update 仍可用；DISABLE_UPDATES=1 会连手动升级一起禁用。

# 卸载原生安装
rm -f ~/.local/bin/claude
rm -rf ~/.local/share/claude
# 连配置一起删（会删除设置、MCP 配置和全部会话历史）
rm -rf ~/.claude ~/.claude.json

注意

  • command not found: claude：~/.local/bin 不在 PATH。执行 echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc && source ~/.bashrc。
  • 有订阅但环境里残留 ANTHROPIC_API_KEY 时，确认后会改走 API 计费。unset ANTHROPIC_API_KEY 并从 ~/.bashrc 删掉 export，再看 /status。
  • --bare 模式不读 CLAUDE_CODE_OAUTH_TOKEN，只认 ANTHROPIC_API_KEY 或 apiKeyHelper。
本机

本机约 1GB 内存，低于官方建议的 4GB。如果安装或长会话出现 Killed（退出码 137），官方给的办法是加 2GB swap：sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile。

入门 · A5

会话管理与撤销

claude -cclaude -rclaude -n/rewind

每个会话都自动保存在本地，可以随时继续、按名字恢复或分叉。Claude 每次改文件前会打检查点，改坏了可以回退。

会话存在哪

转录文件是 JSONL，位于 ~/.claude/projects/<项目路径转义>/<session-id>.jsonl，默认保留 30 天，由 cleanupPeriodDays 控制。

继续与恢复

命令作用
claude -c（--continue）继续当前目录最近一次会话
claude -r（--resume）打开会话选择器
claude -r 名称或ID直接恢复指定会话；按 ID 恢复可在任意目录执行
claude -n auth-refactor启动时命名；会话内用 /rename
claude --from-pr 123恢复与某个 PR 关联的会话
claude -c --fork-session基于旧会话开一个新 ID，原会话不动
claude -p --resume ID --output-format json "继续"脚本里接着某个会话追问

选择器快捷键：↑↓ 或 jk 移动，Enter 恢复，Space 预览，Ctrl+R 重命名，/ 搜索（可直接粘贴 PR 链接），Ctrl+A 显示所有项目，Ctrl+W 显示同仓库所有 worktree，Ctrl+B 只看当前分支。

检查点与回退

每次你发出一条开启新回合的提示前，Claude Code 会记录 Claude 用文件工具改过的文件状态。打开回退菜单有两种方式：空输入框连按两次 Esc，或输入 /rewind。选中某条历史提示后有这些选项：

选项效果
Restore code and conversation代码和对话都回到那一刻
Restore conversation只回退对话，保留当前代码
Restore code只回退文件，保留对话
Summarize from here把这条之后的对话压缩成摘要（不动文件）
Summarize up to here把这条之前的对话压缩，保留之后的消息
Never mind取消

教程：试错后干净地回退

  1. 让 Claude 按方案 A 修改，跑完发现方向不对。
  2. 在空输入框按 Esc Esc，选中发出方案 A 的那条提示。
  3. 选 Restore code and conversation。文件和对话回到方案 A 之前，那条提示的原文回到输入框。
  4. 改写提示，改用方案 B 重新发送。想同时保留两条路线，就先 /branch plan-b 再试。

注意

  • 检查点只跟踪 Claude 文件工具（Edit、Write 等）的修改。只被 Bash 改过的文件（如 sed -i、构建产物、代码生成）不会恢复。
  • 大部分子代理的改动不在检查点里，包括后台 fork 和 /code-review --fix。你手动改的、其他会话改的也不跟踪。
  • 每个会话保留最近 100 个检查点，约 30 天后清理。官方原话：检查点不能替代版本控制，重要节点仍要 git commit。
  • 恢复会话不会还原这些启动参数，需要重新传：--mcp-config、--plugin-dir、--add-dir、--settings、--fallback-model、--tools、--allowedTools、--disallowedTools。
  • claude -p 和 Agent SDK 产生的会话不出现在选择器和 -c 中；claude -p -c 能找到它们。

模型、推理力度与快速模式

/model/effort/fast--fallback-model

三个旋钮各管一件事：模型决定能力上限，推理力度决定每次想多深，快速模式用更高单价换更快的输出。

模型别名

别名含义（Anthropic API）
opus / best最新 Opus，当前为 Opus 5.5，适合复杂推理
sonnet最新 Sonnet，当前为 Sonnet 5.5，日常编码
haikuHaiku 5.5，简单任务、快
fableFable 5.2
opusplanplan 模式用 Opus，执行阶段用 Sonnet
opus[1m] / sonnet[1m]1M 上下文窗口；Fable、Sonnet 5+、Haiku 5.5、Opus 4.7+ 默认已是 1M
default清除覆盖，回到账号默认

需要锁定版本时写完整名称，例如 claude-opus-5-5。设置模型的方式按优先级从高到低：

  1. 会话内 /model 别名，或 /model 打开选择器（Enter 保存为默认，s 只用于本会话）；Alt+P（macOS 为 Option+P）不清空输入就能切换
  2. 启动参数 claude --model sonnet
  3. 环境变量 ANTHROPIC_MODEL
  4. 设置文件里的 model
  5. 环境变量 ANTHROPIC_DEFAULT_MODEL（新会话的起始模型）

推理力度 effort

级别为 low、medium、high、xhigh、max。Opus 5.5、Sonnet 5.5、Haiku 5.5、Fable 5.2 默认 medium。力度越高，回答越深入，耗时和 token 也越多。

/effort high          # 本会话设为 high
/effort               # 打开滑块
/effort auto          # 交给模型默认
/effort status        # 查看当前值
claude --effort xhigh # 启动时指定
export CLAUDE_CODE_EFFORT_LEVEL=high   # 优先级最高
~/.claude/settings.json
{
  "model": "opus",
  "modelSettings": {
    "claude-opus-5-5": { "effortLevel": "xhigh" }
  }
}
  • 设置项 effortLevel 接受 low～xhigh，不接受 max；max 只对当前会话有效，除非用环境变量设置。
  • 在提示里写 ultrathink，只对这一轮要求更深的思考。
  • 参考用法：机械性批量修改用 low／medium；多线程、跨模块设计用 high／xhigh；疑难并发问题临时开 max。
本机

你的用户设置正是上面的写法，Opus 默认 xhigh。日常小改动可以 /effort medium 省额度；在 Opus 5.5 上切换力度不会让提示缓存失效。

备用模型与子代理模型

claude --fallback-model sonnet,haiku    # 主模型繁忙或不可用时按顺序回退，每回合开始重试主模型
export CLAUDE_CODE_SUBAGENT_MODEL=sonnet # 子代理默认模型

快速模式

同一个模型换成侧重速度的 API 配置，输出最多快约 2.5 倍，质量不变，单价更高。支持 Fable 5.2、Opus 5.5、Opus 5；Opus 4.8 的快速模式已弃用，2026-11-30 移除。

模型输入（每百万 token）输出（每百万 token）
Fable 5.2$16$80
Opus 5.5$8$40
Opus 5$10$50
 
/fast            # 空格切换、回车确认；开启后提示符旁出现 ↯
/fast on | off
claude -p --settings '{"fastMode": true}' "..."   # 非交互模式开启
  • 订阅账号的快速模式从 usage credits 扣费，不计入套餐额度，需先开启 usage credits；Team／Enterprise 需 Owner 先启用。
  • 在会话开头就开启。中途第一次开启时，整段上下文按未缓存价格重算；快速和标准模式的缓存互相独立。
  • 快捷键 Alt+O；设置 "fastMode": true 默认开启；"fastModePerSessionOptIn": true 让每个会话从关闭开始；CLAUDE_CODE_DISABLE_FAST_MODE=1 彻底禁用。
  • Bedrock、Foundry 不支持。触发快速模式的独立限流时会自动回落到标准速度，↯ 变灰。

settings.json 与权限规则

/config/permissions--settings--permission-mode

所有行为开关集中在几层 settings.json 里。权限规则决定哪些工具调用直接放行、哪些要问、哪些直接拒绝；权限模式决定没有规则命中时怎么处理。

配置文件层级

优先级位置影响范围
1（最高）托管设置 managed-settings.json 等组织统一下发
2命令行 --settings 文件或JSON仅本次会话
3.claude/settings.local.json你自己、本项目；首次写入时自动加入全局 git excludes
4.claude/settings.json项目所有人，提交到仓库
5~/.claude/settings.json你自己、所有项目
  • 同名的普通键高层覆盖低层；permissions.allow 这类数组会跨文件合并。
  • ~/.claude.json 保存账号、MCP 配置、项目信任状态和 /config 写入的全局开关，不要把权限或钩子写进去。
  • 修改会热加载。JSON 不支持注释和尾逗号；写错时 claude doctor 会列出被拒绝的条目，/status 的 Setting sources 显示加载了哪些文件。
  • 项目文件里的 allow 规则、additionalDirectories 和大部分 env 要等你信任该目录后才生效；deny 和 ask 立即生效。defaultMode 的 auto 和 bypassPermissions 写在项目文件里会被忽略。
  • env 里的值原样使用，~ 和 $HOME 不会展开，要写绝对路径。

改配置的四种途径：直接编辑文件；/config key=value；/permissions 界面；或者让 Claude 用 /update-config 帮你改。权限弹窗里选“Yes, and don't ask again”会写入仓库根目录的 .claude/settings.local.json。

权限规则语法

评估顺序固定为 deny → ask → allow，按这个顺序第一个命中的决定结果，规则写得多具体都不改变顺序。所以宽泛的 deny 无法被更具体的 allow 打开例外。

写法匹配什么
Bash所有 Bash 命令（写在 deny 里会把工具整个移除）
Bash(npm run build)完全相同的命令
Bash(git log *)git log 及带参数的形式；Bash(ls *) 不匹配 lsof，Bash(ls*) 会匹配
Bash(ls:*)等价于 Bash(ls *)
Read(./.env)当前目录下的 .env
Read(~/Documents/*.pdf)从家目录开始的路径
Read(//etc/**)绝对路径要写两个斜杠；单斜杠 /src/** 表示相对设置文件所在的项目根
Edit(src/**/*.ts)覆盖所有写文件的工具；不存在 Write(...)、Grep(...) 规则
WebFetch(domain:example.com)该域名；子域名另写 domain:*.example.com
mcp__github__*某个 MCP 服务器的全部工具
Agent(Explore)某个子代理
Bash(run_in_background:true)按工具参数匹配
  • 复合命令（&&、||、;、|、换行）要求每一段都被允许；deny 和 ask 对任意一段生效，包括 $(...) 里的。
  • timeout、time、nice、nohup、xargs 等包装会先剥离再匹配。

示例：本仓库可用的权限基线

.claude/settings.json
{
  "permissions": {
    "allow": [
      "Bash(./scripts/build.sh debug *)",
      "Bash(./scripts/build.sh format *)",
      "Bash(./scripts/build.sh playground-run *)",
      "Bash(git status)",
      "Bash(git diff *)",
      "Bash(git log *)"
    ],
    "ask": [
      "Bash(git push *)",
      "Bash(./scripts/build.sh sanitize *)",
      "Bash(./scripts/build.sh tsan *)",
      "Bash(./scripts/build.sh clang-tidy *)"
    ],
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)"
    ]
  }
}

ask 里的三条对应 AGENTS.md 中“暂不执行 sanitize、TSan、clang-tidy”的约定：即使在 auto 模式下，命中 ask 规则也一定会弹窗。

权限模式

模式状态栏行为
default（Manual）⏸ manual mode on工作目录内的读取直接放行，编辑、命令、联网逐个询问
acceptEdits⏵⏵ accept edits on自动接受工作目录内的文件编辑和 mkdir、mv、cp 等文件命令
plan⏸ plan mode on只读探索并出方案，批准前不改源码
auto⏵⏵ auto mode on后台分类器逐个审查动作，拦截越权、破坏性或受外部内容诱导的操作（见 C8）
dontAsk⏵⏵ don't ask on凡是需要询问的一律拒绝，只执行规则明确允许的操作；适合脚本
bypassPermissions⏵⏵ bypass permissions on跳过所有询问（deny 仍生效），只应在容器或虚拟机里用

切换方式：Shift+Tab 循环；claude --permission-mode plan；设置 permissions.defaultMode。从 2.1.283 起，终端和 VS Code 的新会话默认就是 auto，claude -p 默认 default。

教程：给仓库建立权限基线

  1. /permissions 查看当前全部规则及每条来自哪个文件。
  2. 运行 /fewer-permission-prompts，它扫描你的历史转录，把常用的只读命令整理成白名单写进项目的 .claude/settings.json。
  3. 按上面的示例补充 ask 和 deny。
  4. 在 shell 里运行 claude doctor 校验文件没有写错。
  5. 再开 /permissions 确认规则都已加载。

注意

  • Bash 规则匹配的是命令文本，不是程序本身。Bash(git push *) 拦不住 git -C . push，Bash(rm *) 拦不住 /bin/rm 或 find -delete。要硬性保证，用 PreToolUse 钩子或沙箱（C8）。
  • .claudeignore 不起作用，敏感文件要写成 Read(...) 的 deny 规则。

状态栏

最快的办法是用自然语言描述，Claude Code 会在 ~/.claude/ 下生成脚本并改好设置：

/statusline 显示模型名、推理力度、当前目录、git 分支，第二行显示上下文进度条和本会话花费
/statusline delete       # 删除状态栏

手动配置时，状态栏是一个从 stdin 读 JSON、往 stdout 打印文字的命令。每个 print 是一行，支持 ANSI 颜色和 OSC 8 链接。下面这个 Python 版本不依赖 jq：

~/.claude/statusline.py
#!/usr/bin/env python3
import json, os, subprocess, sys

d = json.load(sys.stdin)
model = (d.get("model") or {}).get("display_name", "?")
cwd = (d.get("workspace") or {}).get("current_dir", "")
pct = int((d.get("context_window") or {}).get("used_percentage") or 0)
cost = (d.get("cost") or {}).get("total_cost_usd") or 0
effort = (d.get("effort") or {}).get("level", "")

bar = "▓" * (pct // 10) + "░" * (10 - pct // 10)
try:
    branch = subprocess.run(["git", "-C", cwd, "branch", "--show-current"],
                            capture_output=True, text=True, timeout=1).stdout.strip()
except Exception:
    branch = ""

tag = f"{model} · {effort}" if effort else model
line1 = f"[{tag}] {os.path.basename(cwd)}"
if branch:
    line1 += f" ⎇ {branch}"
print(line1)
print(f"{bar} {pct}% · ${cost:.2f}")
~/.claude/settings.json
{
  "statusLine": {
    "type": "command",
    "command": "python3 ~/.claude/statusline.py",
    "padding": 1
  }
}

claude --bg "排查 game_timer 偶发晚投递的原因，给出复现步骤"
claude --bg -n timer-race "同上"                 # 起个名字，之后可以用名字操作
claude --resume <session-id> --bg "接着完成迁移"   # 把已有会话放到后台继续

启动后会打印：

backgrounded · 7c5dcf5d · timer-race
  claude agents             list sessions
  claude attach 7c5dcf5d    open in this terminal
  claude logs 7c5dcf5d      show recent output
  claude stop 7c5dcf5d      stop this session

正在进行的会话也能转后台：输入 /bg，或在空输入框按 ←（同时打开 agent view）。/fork 把整段对话复制成一个新的后台会话，你在当前会话继续。

命令作用
claude agents打开 agent view；--json 输出会话列表供脚本用，--cwd 路径 只看某目录
claude attach ID或名称在当前终端接入；← 回到 agent view，Ctrl+Z 回 shell，会话照常运行
claude logs ID或名称打印最近输出
claude stop ID（kill）停止，对话保留，之后 attach 可恢复
claude rm ID从列表移除，安全时删除其 worktree；对话仍可用 claude --resume 找回
claude respawn ID / --all重启会话以使用当前版本的 Claude Code
claude daemon status / logs / stop查看或停止监管进程（日志在 ~/.claude/daemon.log）

agent view 操作

  • 会话按状态分组：Pinned、Ready for review、Needs input、Working、Completed。
  • Enter 或 → 接入；Space 打开预览面板，可以直接回复，回复前加 ! 发 Bash 命令，只写 /stop 则停止该会话。
  • Ctrl+X 停止，两秒内再按一次删除；Ctrl+T 置顶（空闲时也保持进程）；Ctrl+R 重命名；? 查看全部快捷键。
  • 底部输入框输入提示后回车会派发一个新会话。前缀 @代理名 指定自定义子代理，! 命令 跑后台 shell 任务；s:working、n:名称 等可以过滤列表。
  • 后台会话需要输入、完成或失败时会发终端通知。

Worktree

claude -w feature-auth          # 在 .claude/worktrees/feature-auth 建 worktree，分支 worktree-feature-auth
claude -w "#1234"               # 基于 PR 建 worktree（.claude/worktrees/pr-1234）
claude -w feature-auth --tmux   # 同时为它开一个 tmux 会话
claude -w feature-auth --resume # 回到保留下来的 worktree 会话
  • 派发到后台的会话在第一次改文件前会自动进入 .claude/worktrees/ 下的 worktree；设置 "worktree": {"bgIsolation": "none"} 可关闭。
  • 新 worktree 默认从远端默认分支切出；设置 "worktree": {"baseRef": "head"} 改为从本地 HEAD 切出。
  • 被 gitignore 的文件（如 .env）不会出现在新 worktree 里，在仓库根写 .worktreeinclude（gitignore 语法）列出要复制的文件。
  • 退出时，干净的无名 worktree 自动删除；有改动的会询问保留还是删除。-p 模式不会清理，要自己 git worktree remove。
  • 建议把 .claude/worktrees/ 加进 .gitignore。

会话之间互发消息

/list-agents（/peers）列出可以联系的子代理和其他会话。直接对 Claude 说“告诉 @timer-race 我已经把 queue 的修复合进来了”，它会用 SendMessage 工具投递；输入 @ 加名字前几个字母可以补全。别的会话发来的消息不能批准权限弹窗，里面的斜杠命令也只当文本。/config 里的 Messages from your other sessions 可设为 accept、hold 或 refuse。

教程：三个任务并行

  1. 提交或暂存当前改动，确保主检出是干净的。
  2. 派发两个后台任务： 
    claude --bg -n readme-sync "核对 README 和 AGENTS.md 中的构建命令是否与 scripts/build.sh 一致，列出差异"
claude --bg -n review "对当前分支相对 main 的改动执行 /code-review high，只报告不修改"
  3. 在前台继续自己的主任务。需要时运行 claude agents，Space 查看进度并直接回复。
  4. 任务完成后 claude attach review 查看结果。有文件改动的会话先在它的 worktree 里提交并合并分支，再 claude rm。

注意

  • 后台会话和交互会话一样消耗订阅额度，十个并行约等于十倍速度消耗。
  • 在 agent view 里删除会话会一并删除 Claude 为它创建的 worktree，删除前先提交改动。
  • 后台会话跑在本机：机器休眠时保留，关机或重启后停止。完成或等待中的会话无人接入约一小时后进程会停，对话保存在磁盘，接入或回复时恢复。
本机

这台机器只有 1 vCPU、约 1GB 内存、磁盘剩余约 11GB。每个 worktree 都会有自己的 build-* 目录，同时跑两个以上需要编译的会话会互相拖慢并占满磁盘，建议同一时间只让一个后台会话做构建。

安全是分层的：权限规则（B2）管单个调用，权限模式管默认态度，auto 模式的分类器替你审批，Bash 沙箱在操作系统层面限制命令，容器或虚拟机隔离整个进程。

Bash 沙箱

维度沙箱内的默认行为
覆盖范围只管 Bash、PowerShell、Monitor 命令及其子进程。Read、Edit、WebFetch、MCP 服务器、钩子不在沙箱内

教程：在 Linux 上启用

  1. 安装依赖并重启 Claude Code：sudo apt-get install bubblewrap socat。
  2. 会话里运行 /sandbox。Mode 标签选择 auto-allow（沙箱内命令免询问）或 regular permissions（照常询问）；选择保存在 .claude/settings.local.json。
  3. 让 Claude 执行两条验证命令（不要在 ! 模式下自己跑）：touch ~/sandbox-probe 应报 Read-only file system；curl --noproxy '*' https://example.com 应报 Could not resolve host。
  4. 按需在设置里放开域名、写路径，并把凭据挡在外面：
.claude/settings.local.json
{
  "sandbox": {
    "enabled": true,
    "failIfUnavailable": true,
    "allowUnsandboxedCommands": false,
    "excludedCommands": ["docker compose *"],
    "filesystem": {
      "allowWrite": ["/tmp/build"]
    },
    "network": {
      "allowedDomains": ["github.com", "*.github.com"]
    },
    "credentials": {
      "files": [{ "path": "~/.ssh", "mode": "deny" }],
      "envVars": [{ "name": "GITHUB_TOKEN", "mode": "deny" }]
    }
  }
}
  • failIfUnavailable: true：沙箱不可用时直接退出，而不是悄悄无沙箱运行。
  • allowUnsandboxedCommands: false（严格模式）：忽略 Claude 用 dangerouslyDisableSandbox 绕出沙箱重试的请求。
  • excludedCommands 里的命令在沙箱外运行，模式以 * 结尾。
  • 只想临时试一次：claude --settings '{"sandbox": {"enabled": true, "allowUnsandboxedCommands": false}}'。

auto 模式的规则

auto 模式下，分类器会拦下它判断为不可逆、破坏性或指向你环境之外的操作，默认只信任工作目录和当前仓库已配置的远端。deny 和显式的 ask 规则先于分类器生效。想让它认识你的基础设施，就在 autoMode 里用自然语言描述：

~/.claude/settings.json
{
  "autoMode": {
    "environment": [
      "$defaults",
      "Source control: github.com/your-org and all repos under it"
    ],
    "soft_deny": [
      "$defaults",
      "Never run ./scripts/build.sh sanitize, tsan or clang-tidy unless explicitly asked"
    ],
    "hard_deny": [
      "$defaults",
      "Never send repository contents to third-party code-review APIs"
    ]
  }
}
  • 四个列表：environment（可信环境）、allow（对 soft_deny 的例外）、soft_deny（默认拦截，用户明确要求时可放行）、hard_deny（无条件拦截）。每个列表都要包含 "$defaults"，否则会丢掉内置规则。
  • 只从用户设置、托管设置和 --settings 读取，项目里的 .claude/settings.json 不生效，防止仓库给自己开后门。
  • 泛泛的请求不算明确授权：“清理一下仓库”不会授权 force push，“force push 这个分支”才算。
claude auto-mode defaults     # 打印内置规则；--label 'Git Destructive' 过滤
claude auto-mode config       # 打印合并后实际生效的规则
claude auto-mode critique     # 让 AI 点评你的自定义规则
claude auto-mode reset        # 删除用户设置里的 autoMode 段
/auto-mode-setup              # 会话内起草 environment 条目

bypassPermissions 与整进程隔离

  • --dangerously-skip-permissions 等同 --permission-mode bypassPermissions，跳过所有询问，连 .git、.claude 这些受保护路径的写入也不问。只在容器、虚拟机或 sandbox runtime 里用；在 Linux 和 macOS 上以 root 运行时它会拒绝启动。
  • --allow-dangerously-skip-permissions 只把 bypass 加进 Shift+Tab 循环，不直接进入。
  • 组织可以在托管设置里写 "disableBypassPermissionsMode": "disable" 禁用。
  • 整进程隔离（连文件工具、MCP、钩子一起关进去）：npm install -g @anthropic-ai/sandbox-runtime 后运行 srt claude；或用官方 dev container、自建容器、虚拟机、云端会话。

  • 沙箱只管 shell 命令。denyRead 挡不住 Read 工具，allowedDomains 不限制 WebFetch，这两者要靠权限规则。
  • 放开宽泛的域名可能成为数据外泄通道；把 /var/run/docker.sock 加进可写路径基本等于交出宿主机。
  • MCP 服务器只用自己写的或可信来源的；审查 .mcp.json 看不到其他作用域、连接器和插件带进来的服务器。
本机

本机没装 bubblewrap 和 socat，现在开 /sandbox 会因依赖检查失败而退回无沙箱运行；先安装依赖，并建议同时设 failIfUnavailable: true。

花费主要由三件事决定：每次请求带多少上下文、提示缓存命中多少、用什么模型和力度。先测量，再调整。

怎么看花费

  • /usage（别名 /cost、/stats）：本会话花费、按模型的 token 明细、套餐额度、活动统计，以及 Prompt cache (main) 一行的缓存命中情况。订阅用户看到的是额度进度条。
  • /context：哪类内容占了上下文。/skill-doctor：每个 skill 占多少上下文、用得多不多。/insights：最近会话的使用模式报告。
  • 参考数字（官方企业平均，按 API 价格）：每位开发者每个活跃日约 13 美元，每月 150～250 美元，90% 的用户每日低于 30 美元。

提示缓存

每次请求都会发送完整上下文，API 复用与上次相同的前缀。前缀一变，后面全部重算，这一轮就又慢又贵。

缓存有效期：订阅账号套餐内的主对话是 1 小时，API Key、usage credits 或云厂商是 5 分钟，子代理等辅助请求默认 5 分钟。promptCacheTtl 或 CLAUDE_CODE_PROMPT_CACHE_TTL（5m／1h）可以调整。

教程：一次成本体检

  1. 在一个干了一阵活的会话里运行 /usage，看缓存命中率和未命中次数。
  2. /context 找出大头：MCP 工具、说明文件、超长的工具输出。
  3. /skill-doctor 看有没有很少用却常驻的 skill，用 /skills 调整可见性。
  4. 调整：停用闲置 MCP、精简说明文件、日常任务改用 /effort medium。
  5. 一周后再看 /usage 的 Stats 标签对比。

性能

  • 会话堆内存超过 2.5GB 会出警告：重启后 claude -c 继续。全屏渲染器（/tui fullscreen）在长对话里内存更平稳。
  • --fallback-model sonnet 在主模型过载时自动回退，减少等待。
  • 升级后的第一轮必然不命中缓存；想自己控制升级时机就设 DISABLE_AUTOUPDATER=1，空闲时手动 claude update。
本机

你是订阅账号，主对话享受 1 小时缓存；同时开了 autoContinueAtUsageLimit，触及额度上限后会等重置再自动继续（最多连续三次）。Opus 默认 xhigh 是额度消耗的主要来源，可以先从这里调。

教程：配置不生效时的排查流程

  1. claude --safe-mode 启动。问题消失，说明出在 CLAUDE.md、skill、插件、钩子或 MCP 之一。
  2. /context 确认目标文件是否加载。子目录 CLAUDE.md 要等读写该目录文件时才加载。
  3. claude doctor 查无效设置，/status 看加载了哪些设置来源。记住优先级：托管 > 命令行 > local > project > user。
  4. MCP 问题看 /mcp。项目 .mcp.json 的服务器需要一次性批准，想重新弹出批准用 claude mcp reset-project-choices；显示已连接但没有工具时用 claude --debug=mcp 看服务器的 stderr。
  5. 钩子问题看 /hooks。matcher 必须是单个字符串，工具名区分大小写，多个工具写 "Edit|Write"。
  6. 仍无头绪就用干净配置复现： 
    mkdir -p ~/claude-clean/empty && cd ~/claude-clean/empty
CLAUDE_CONFIG_DIR=~/claude-clean/config claude --setting-sources user
    问题消失后，把 ~/.claude.json 和 ~/.claude/ 里的文件逐个拷进 ~/claude-clean/config，找出罪魁。
