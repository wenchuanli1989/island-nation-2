# 弗洛伊德算法性能优化

## 优化概述

本文档描述了针对弗洛伊德（Floyd-Warshall）最短路径算法实施的性能优化措施，与 `demo.c` 实现保持一致。优化重点关注减少内存访问、提高缓存命中率和减少不必要的计算。

## 优化策略

### 1. 指针缓存优化

**问题**：每次访问二维数组 `path_matrix[i][j]` 都会产生多次指针解引用，带来额外开销。

**优化**：在循环开始处缓存行指针，减少重复的数组访问。

```c
// 最外层：缓存中间节点对应行
PathInfo* const middle_info = path_matrix[middle_vertex_id];

// 源节点循环：缓存当前源节点行
PathInfo* const source_info = path_matrix[source_vertex_id];

// 内层：缓存当前 (source, target) 的 PathInfo 指针
PathInfo* const source_to_target_info = &(source_info[target_vertex_id]);
```

**效果**：减少内存解引用次数，提高缓存局部性；最外层以中间节点为第一维，也利于访问顺序的局部性。

### 2. 提前终止优化（source → middle 为 INF）

**问题**：若从源节点到中间节点的最短距离为无穷大（INF），则无需对任何目标节点做松弛。

**优化**：在源节点循环内、目标循环前，缓存 `source_to_middle` 并检查 INF，若为 INF 则直接 `continue`，跳过整层 target 循环。

```c
const EdgeWeight source_to_middle = source_info[middle_vertex_id].shortest_distance;
if (source_to_middle >= WEIGHT_INFINITY) {
    continue;  // 跳过后续所有 target 的检查
}
```

**效果**：在稀疏图中可显著减少无效内层迭代。

### 3. 中间值缓存

**问题**：`source_info[middle_vertex_id].shortest_distance` 若在内层 target 循环中重复访问，会带来多余内存读。

**优化**：在源节点循环内、进入 target 循环前，将「source → middle」的权值缓存到局部变量；在内层循环中再将「middle → target」的权值缓存。

```c
// 源节点循环内、target 循环外
const EdgeWeight source_to_middle = source_info[middle_vertex_id].shortest_distance;

// target 循环内
const PathInfo* const middle_to_target_info = &(middle_info[target_vertex_id]);
const EdgeWeight middle_to_target = middle_to_target_info->shortest_distance;
```

**效果**：减少内层循环中的内存访问次数。

### 4. 双重 INF 检查

**问题**：即使 `source_to_middle` 非 INF，`middle_to_target` 仍可能为 INF，此时无需计算 `new_weight` 和更新。

**优化**：在内层循环中检查 `middle_to_target >= WEIGHT_INFINITY`，若成立则 `continue`。

```c
if (middle_to_target >= WEIGHT_INFINITY) {
    continue;  // 不需要更新
}
const EdgeWeight new_weight = source_to_middle + middle_to_target;
// 若新路径更短，更新距离并同步前驱与分叉ID
if (new_weight < source_to_target_info->shortest_distance) {
    source_to_target_info->shortest_distance = new_weight;
    source_to_target_info->pre_vertex_id = middle_to_target_info->pre_vertex_id;
    source_to_target_info->pre_road_fork_id = middle_to_target_info->pre_road_fork_id;
}
```

**效果**：避免无效的加法与比较，并减少写回；松弛时同时更新前驱顶点与分叉 ID，与 `PathInfo` 定义一致。

### 5. 初始化优化：按边写入 O(N + E)

**问题**：若用邻接矩阵逐对查边初始化，复杂度为 O(N²)；且存在大量重复数组访问。

**优化**：使用邻接表（`VertexEdges`）按边写入。对每个源点：先将整行设为 INF / `PRE_VERTEX_NULL` / `pre_road_fork_id = 0`，将自身距离设为 0；再遍历该源点的出边，只对有边的目标写入权值、前驱与分叉 ID。初始化总复杂度为 O(N + 总边数)，稀疏图下远快于 O(N²)。

```c
PathInfo* const source_info = path_matrix[source_vertex_id];
// 先整行初始化
for (VertexID target_vertex_id = 0; target_vertex_id < vertex_num; target_vertex_id++) {
    PathInfo* const path_info = &(source_info[target_vertex_id]);
    path_info->shortest_distance = WEIGHT_INFINITY;
    path_info->pre_vertex_id = PRE_VERTEX_NULL;
    path_info->pre_road_fork_id = 0;
}
PathInfo* const self_path_info = &(source_info[source_vertex_id]);
self_path_info->shortest_distance = 0;
self_path_info->pre_vertex_id = PRE_VERTEX_NULL;

const VertexEdges* const vert_edges = &vertices[source_vertex_id];
for (int i = 0; i < vert_edges->count; i++) {
    const Edge* const edge = &(vert_edges->edges[i]);
    if (edge->weight > 0 && edge->weight < WEIGHT_INFINITY && edge->target_vertex_id != source_vertex_id) {
        PathInfo* const target_path_info = &(source_info[edge->target_vertex_id]);
        target_path_info->shortest_distance = edge->weight;
        target_path_info->pre_vertex_id = source_vertex_id;
        target_path_info->pre_road_fork_id = vert_edges->road_fork_id;
    }
}
```

**效果**：稀疏图下初始化时间明显降低；同时配合行指针 `source_info` 减少访问开销。实现中会对初始化阶段计时并打印（`算法初始化时间`）。

### 6. 路径构建：用栈替代递归（find_shortest_path）

**问题**：若用递归根据 `pre_vertex_id` 从终点回溯到起点，深度较大时存在栈溢出风险且调用开销高。

**优化**：在 `find_shortest_path` 中从终点沿 `path_matrix[start_vertex_id][current].pre_vertex_id` 回溯到起点，将路径上的 `PathInfo` 依次写入 `shortest_path_info`，并用栈结构控制写入顺序；同时通过 `road_fork_count` 返回路径分叉数量。实现 O(路径长度) 的线性空间、无递归。

**效果**：避免递归栈溢出，且常数开销更小；便于调用方直接使用路径信息与分叉 ID。

## 优化技巧总结

1. **减少内存访问**：用局部变量缓存 `source_to_middle`、`middle_to_target` 及行指针（`middle_info`、`source_info`）
2. **提高缓存命中率**：最外层以中间节点为第一维（算法要求），行指针缓存，访问连续
3. **提前终止**：先判断 `source_to_middle >= WEIGHT_INFINITY` 再进入 target 循环；内层再判断 `middle_to_target >= WEIGHT_INFINITY`
4. **跳过无效下标**：显式跳过 `source == middle`、`source == target`、`target == middle`，避免无意义读写
5. **初始化与路径构建**：初始化按边写入 O(N+E)，并设 `pre_road_fork_id`；松弛时同步更新 `pre_vertex_id` 与 `pre_road_fork_id`；`find_shortest_path` 用栈回溯构建路径，避免递归

## 进一步优化建议


### 1. 数据结构优化
- 对于超稀疏图，考虑使用邻接表而非邻接矩阵
- 使用位运算优化某些操作

### 2. 算法替代
- 对于单源最短路径问题，Dijkstra算法可能更高效
- 对于所有点对最短路径，在某些情况下Johnson算法可能更快

### 3. 编译优化
- 使用 `-O3` 优化级别
- 启用链接时优化（LTO）
- 使用特定于处理器的优化选项（如 `-march=native`）

### 4. 二维数组分配（若自分配矩阵）
- 若需自行分配路径矩阵，建议使用连续二维数组以利于缓存：  
  `PathInfo (*path_matrix)[vertex_num] = malloc((size_t)vertex_num * sizeof(PathInfo[vertex_num]))`  
  避免使用 `PathInfo**` 的指针数组形式。

### 5. 统计与计时（与 demo.c 一致）
- 初始化阶段使用 `clock()` 计时并打印「算法初始化时间」。
- 主循环中统计并打印：`total_tick`（内层循环进入次数）、`hit_tick`（实际松弛次数）、`null_weight_count`（因 source→middle 为 INF 而跳过的 source 数）、`null_weight_count_inner`（因 middle→target 为 INF 而跳过的 target 数）。稀疏图下后两者会很大，可用来验证提前终止是否生效。

## 稀疏图下的性能收益（小结）

- **单一路径矩阵**：只维护 `path_matrix`（PathInfo），不另存 N×N 边权矩阵，减少内存占用与缓存竞争。
- **按邻接表写边**：初始化只遍历实际存在的边（每点最多 8 条），不读 N×N 边表，访问模式简单、缓存友好。
- **主循环提前终止**：利用稀疏图中大量 INF，在 source→middle 或 middle→target 为 INF 时直接跳过，减少实际迭代与访存。

| 方面       | 做法                         | 稀疏图下的收益         |
|------------|------------------------------|------------------------|
| 初始化     | 按行初始化 + 仅按邻接表写边  | 无单独边矩阵、访问简单 |
| 主循环     | 双 INF 提前终止              | 大量跳过内层，少算少访存 |
| 内存与缓存 | 仅 path_matrix + 小邻接表    | 缓存竞争小、命中率更高 |
| 可观测性   | total_tick、hit_tick、null_weight_* 打印 | 可验证提前终止是否生效 |

算法仍为 O(N³)，但在稀疏图上通过「无单独边矩阵 + 按边初始化 + 双重 INF 提前终止」减少实际迭代与内存占用，从而获得明显性能提升。

## 注意事项

1. **代码可读性**：优化不应牺牲代码的可读性和可维护性
2. **正确性**：所有优化都必须保持算法的正确性
3. **测试**：优化后应进行充分的测试，确保结果一致
4. **平台差异**：某些优化在不同平台上效果可能不同
